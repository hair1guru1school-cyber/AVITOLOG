# СУПЕР ПОДРОБНОЕ ТЗ ДЛЯ CODEX

## 0) Роль и цель
Ты — **GPT-5.2-Codex** в режиме senior/fullstack + product engineer.
Твоя цель: провести **безопасный поэтапный рефакторинг AVITOLOG** из монолита в модульную архитектуру, не ломая текущий функционал, с чёткими артефактами на каждом этапе.

Критерий успеха: после каждой итерации сайт запускается локально и ключевые сценарии работают.

---

## 1) Контекст проекта
- Текущий проект: одностраничный HTML-монолит (`index.html`) с большим объёмом inline CSS/JS.
- В проекте присутствуют функции CRM, генерация, цели/аналитика, интеграции, локальное хранение данных.
- Нужна **декомпозиция на 5–8 пакетов (модулей)**, улучшение поддерживаемости и повторяемая сборка/деплой.

---

## 2) Жёсткие ограничения (обязательно)
1. Не ломать бизнес-логику и UI поведение.
2. Любой этап должен быть обратимым (маленькие атомарные коммиты).
3. Перед правками составить карту зависимостей функций и DOM-узлов.
4. Все новые функции документировать JSDoc.
5. Не хранить секреты в коде/репозитории.
6. Результат каждого этапа: changelog + список рисков + план rollback.

---

## 3) Целевая структура (8 основных пакетов)
Создай такую архитектуру (можно корректировать имена, но сохранить смысл):

1. `src/core/` — boot, init, router tabs, global state
2. `src/ui/` — рендеры, компоненты, popups, overlays
3. `src/crm/` — клиенты, карточки, бейджи, фильтры, поиск
4. `src/goals/` — цели, недели, статусы, суммы, архив
5. `src/integrations/` — google drive/api, внешние сервисы
6. `src/storage/` — localStorage/sessionStorage adapters, миграции
7. `src/utils/` — helpers (date, sanitize, format, dom)
8. `src/styles/` — базовые/компонентные стили, токены темы

Дополнительно:
- `public/assets/` — изображения/иконки
- `docs/` — техдоки, ADR, миграции
- `scripts/` — служебные скрипты

## 4) Этапы работ (итерации)

### Итерация 1 — Аудит и карта проекта
Сделай:
- Инвентаризацию глобальных переменных
- Граф зависимостей функций
- Список inline handlers (`onclick/oninput/...`)
- Карта localStorage ключей
- Таблица рисков

Артефакты:
- `docs/01-audit.md`
- `docs/01-dependency-map.md`
- `docs/01-storage-map.md`

### Итерация 2 — Вынос CSS
Сделай:
- Перенос inline CSS в `src/styles/*.css`
- Токены темы в отдельный файл
- Удаление дубликатов стилей

Артефакты:
- `src/styles/tokens.css`
- `src/styles/layout.css`
- `src/styles/components.css`
- `docs/02-styles-migration.md`

### Итерация 3 — Core + Bootstrap
Сделай:
- Единый `initApp()`
- Убрать множественные `DOMContentLoaded`
- Перенос базовой инициализации в `src/core/bootstrap.js`

Артефакты:
- `src/core/bootstrap.js`
- `src/core/state.js`
- `docs/03-core-init.md`

### Итерация 4 — CRM пакет
Сделай:
- Вынести CRM-логику в `src/crm/*`
- Ввести сервисный слой и слой рендера
- Унифицировать события

Артефакты:
- `src/crm/service.js`
- `src/crm/render.js`
- `src/crm/events.js`

### Итерация 5 — Goals пакет
Сделай:
- Перенести цели/недели/статусы в `src/goals/*`
- Вынести вычисления и форматирование

Артефакты:
- `src/goals/service.js`
- `src/goals/render.js`
- `src/goals/events.js`

### Итерация 6 — Integrations + Storage
Сделай:
- Обёртки `DriveClient`, `StorageClient`
- Обработка ошибок и истечения сессий
- Подготовить миграции ключей localStorage

Артефакты:
- `src/integrations/drive.client.js`
- `src/storage/storage.client.js`
- `src/storage/migrations.js`

### Итерация 7 — QA/Smoke/Test
Сделай:
- Smoke-чеклист ручного тестирования
- Базовые unit/e2e тесты критичных функций
- Перф-проверка (размер, время init)

Артефакты:
- `docs/07-smoke-checklist.md`
- `tests/smoke/*.spec.js`
- `docs/07-perf-baseline.md`

### Итерация 8 — Release
Сделай:
- Релизные заметки
- Инструкцию обновления
- План отката

Артефакты:
- `docs/08-release-notes.md`
- `docs/08-rollback.md`

---

## 5) Формат выполнения от Codex (обязательный)
Каждую итерацию отдавай строго в формате:
1. Что сделал
2. Какие файлы изменил
3. Почему это безопасно
4. Какие риски
5. Какие тесты запускал
6. Что осталось

---

## 6) Критичные сценарии для регрессии
Проверь после каждого этапа:
1. Открытие сайта
2. Переключение вкладок
3. CRM: выбор/создание клиента
4. Сохранение/чтение localStorage
5. Goals: добавление/редактирование/архив
6. Интеграции (если токен доступен)
7. Мобильный сайдбар
8. Закрытие попапов и escape-hotkeys

---

## 7) Definition of Done
Работа считается завершённой, если:
- Монолит разделён на 5–8 модулей (по факту 8 пакетов)
- Нет критичных inline-обработчиков
- Инициализация централизована
- Документация актуальна
- Smoke тесты пройдены
- Есть rollback-план

---

## 8) Стартовая команда Codex
Начни с: аудита, построения dependency-map и предложения безопасного плана миграции **без слома текущего UI**.
